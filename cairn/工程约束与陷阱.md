# 工程约束与陷阱

本文件是 `AGENTS.md` 硬约束一节的完整版。收录的都是**已经付过代价**的
条目——每条尽量写清"当时怎么表现的"和"为什么这么定",以免下次被同一个
坑用不同面貌绊倒。

## 当前结论

### 环境:工作区会静默回滚

容器可能在会话中途被回收,工作区随之退回旧提交,而 `git status` 看起来
完全正常。表现为文件"消失"、刚写的内容不见、`git log` 对不上。

- 处置:`git fetch origin <branch> && git reset --hard origin/<branch>`。
- 已推送的工作从未真正丢失;**未推送的会丢**,所以阶段性成果尽早提交。
- 单次会话中触发过 8 次;有两次发生在"写文件的过程中",导致新内容落在了
  旧树上——所以恢复后要核对关键文件的行数/标志性段落,而不是只看 `git log`。

### 测试:两处不能删的死锁修复

测试套件曾整体死锁,根因是三层叠加的,逐层剥出来的:

1. libgomp 屏障死锁 → `tests/conftest.py` 钉 `OMP_NUM_THREADS=1`;
2. 导入顺序问题 → 同文件里 pandas 预导入;
3. **真正的根因**:Qt widget 的析构函数被 GC 调度到 streamlit 的
   ScriptRunner 线程上执行,在 `QWindow::close → flushWindowSystemEvents`
   处永久阻塞,且持有 GIL,整个 pytest 进程挂死。

`tests/test_gui_qt.py` 的 fixture 因此显式做 `deleteLater()` +
`processEvents()` + `gc.collect()` 拆除。**新增 Qt 测试沿用这套 fixture,
不要自己造。**

### 数值:`np.allclose` 的默认 `atol`

检查时间列是否均匀采样时用了 `np.allclose(dt, dt[0], rtol=1e-6)`——
默认 `atol=1e-8` **秒**,在 100 MHz 以上比采样周期还大,于是抖动的导出被
静默放行,采样率取自它第一个(任意的)步长。写成 `atol=0.0`。

同类风险:任何对"物理量的小绝对值"用 allclose 的地方,都要显式给 atol。

### 校准:首采冻结类量对电平次序敏感

`ThermalReferencePA` 的耗散功率参考、`LoopbackChannel(rx_im3_freeze=True)`
的 κ 都在**第一次调用**冻结。踩到两次:

- 用回退到 0.1 倍的标定采集打头,κ 被冻高约两个量级;
- 用恒包络探针(功率 2.25)标定后再采突发波形(功率 ~0.55),热状态动态
  被压掉 4 倍,状态样条收益从 +10.5 dB 缩水成 +1.8 dB。

规则:标定采集必须在**标称工作电平**先做;表征探针与建模采集各用新建的
DUT 实例。这条对真实台架的采集顺序同样成立。

### 评估:状态模型的冷启动约定

单采集切分成训练/验证后,验证尾段**带着前段的热历史**,而模型的状态递推
从块首因果重算。必须"全信号预测、尾段打分";只对尾段预测等于假设了一个
它并不具备的冷启动,+10 dB 的收益会缩水成 +1。

### CI:矩阵与 test-full 的依赖集不同

快车道矩阵装 torch 但**不装 onnx**;`test-full` 装全套。一个 ONNX 测试
因此在开发机长期通过、云端长期红。写测试不要假设可选依赖存在,该
`pytest.importorskip` 就写上。

配额故障还会**掩盖真实失败**:仓库私有期 runner 未分配,所有 job 在 2 秒
内失败(`runner_id=0`),连续十几次提交都没有真实 CI 信号——转公开后一次
性暴露了两个陈年缺陷。看到"秒级失败 + runner_id=0"就知道不是代码问题。

### 建模:线性参数模型必须用 LS 闭式解

MP/GMP/DDR 这类**对系数线性**的模型一律用最小二乘闭式解,不要改成 SGD
迭代。同一个 GMP 用 SGD 训出来的 ACLR 比闭式解差 9 dB 以上,双重实证过。
只有真正非线性的参数(神经网络、样条结点位置)才需要迭代优化。

### GUI:Qt 侧的线程约定

- 耗时操作走 `FnWorker`,**在 GUI 线程上先把控件值快照成普通 Python 值**
  再传进闭包——worker 线程里访问 `QWidget` 不安全;
- 服务层函数放 `gui_core/services.py`(纯 Python,不 import 任何 GUI),
  两个 GUI 各接一次,不在页面里写算法。

### 文档:性能数字要三处同步

改动性能数字必须同时更新 `README.md`、`docs/05_performance_summary.md`、
`manual/zh|en`——三处曾各说各的。`tests/test_docs_site.py` 会检查 README
提到的每个 Phase 在 `docs/03_roadmap.md` 里存在(路线图曾落后两个阶段)。
改手册跑 `pytest tests/test_manual.py`;改 mkdocs 配置或 API 页跑
`pytest tests/test_docs_site.py`。

### 建模:相位谐波互不可表示

e^{+jφ}(主)、e^{−jφ}(镜像)、e^{−j3φ}(C-IM3)三类相位谐波在结构上
**互相表示不了**,各需专用分支。加新损伤前先判断它属于哪一类;若发生在
PA 之前,大概率存在精确代数预逆(参考 QMC),不必挤进 DPD 基。

## 教训

- **本地通过 ≠ 环境无关**:ONNX 与 streamlit 两个缺陷都是"开发机恰好装了
  某个包 / 版本恰好旧"造成的假绿。判断"这是我的改动还是环境差异"时,先比
  两侧的依赖与版本,再改代码。
- **负结果照写**:C-IM3 六种方案的失败、结构天花板的证明过程,写进
  docstring 与 CHANGELOG 后,直接省掉了别人重走弯路的成本。宁可写"这条路
  不通,因为 X",不要悄悄删。
- **诊断顺序**:遇到"应该能行但不行"的现象,先隔离变量(换 DUT、关损伤、
  缩短信号)再猜原因。测试死锁的三层根因、去嵌器的排序 bug、迟滞比 0.47
  都是靠逐项隔离找出来的,不是靠读代码想出来的。

## 开放问题

- 迟滞比在长观测窗下仍有约 2 倍的估计器偏差(线性 RC 的 DUT 读 0.51),
  目前的处置是**标注不可靠而非修正**。是否改用加热/冷却共享 τ 的联合拟合
  尚未验证——见 `docs/03_roadmap.md` 候选改进。
