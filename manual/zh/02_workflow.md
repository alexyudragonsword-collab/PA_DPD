# 2. 研发工作流全景

## 2.1 从 PA 设计到系统验证

padpd 覆盖 PA + DPD 研发的完整闭环:

![padpd 研发流程](assets/pipeline.png)

1. **PA 设计 / 数据来源**:CMOS/SOI/GaN PA 的晶体管级设计在 EDA 工具中
   完成。本平台以三种方式获得 PA 的输入输出行为数据:
   - **虚拟 DUT**:内置 `ReferencePA`(Wiener-Hammerstein 结构,含记忆
     与强非线性),用于无硬件时跑通全流程;
   - **电路仿真**:Cadence Envelope 分析导出 CSV;
   - **实测**:仪器采集或 OpenDPD 公开测量数据集。
2. **行为建模**:用经典多项式(LS 闭式解,秒级)或神经网络(SGD 训练)
   拟合 PA 的非线性 + 记忆行为,得到可复算、可微分的 PA 数字替身。
3. **数字预失真(DPD)**:在 PA 前级放置预失真器,抵消其非线性。ILA
   从 PA 的后逆最小二乘辨识;DLA 把预失真器与冻结的神经 PA 级联,
   梯度直训。深压缩工作点先做 CFR 削峰。
4. **定点部署**:把浮点模型量化为定点(位宽扫描定精度边界),导出
   FPGA/ASIC 交接产物。
5. **系统验证**:EVM / ACLR / 发射 Mask 判定是否满足 802.11be 要求,
   不满足则回到 DPD/建模迭代。

## 2.2 AI-Native 的三个关键点

与"先设计 PA,再补救线性度"的传统串行流程相比,平台强调:

- **神经模型作为评估代理**:多项式模型带外外推系统性失真,ACLR 读数
  不可信(实测差 12 dB);DPD 效果评估必须用神经代理。这是本工程用
  真实数据验证过的核心结论。
- **建模精度 ≠ DPD 效果**:DDR-Volterra 正向建模只追平 GMP,但作为
  DPD 基函数以 55% 参数全面胜出。选择 DPD 方案要直接评 DPD 后指标。
- **PA/DPD 联合设计**:效率与可线性化之间存在突变的"可逆壁垒"——
  顺序设计冲到最高效率点后 DPD 无法挽救;联合设计页把工作点与 DPD
  复杂度放在同一优化里权衡。

## 2.3 GUI 页面与工作流的对应

| 流程环节 | GUI 页面 | 产物 |
|---|---|---|
| 波形/激励 | 波形工作台 | IQDataset `.npz` |
| 数据接入 | 数据管理 | 注册的数据源 |
| 行为建模 | PA 建模 | 模型(可存 checkpoint)+ run |
| 预失真 | DPD 实验室 | DPD 前后指标 + run |
| 对比分析 | 结果比较 | 指标柱状图 / JSON 导出 |
| 部署 | 部署 | 位宽曲线、ONNX/系数/向量 |
| 联合设计 | 联合设计 | Pareto 表 + 优化轨迹 |

命令行脚本(`scripts/`)提供与 GUI 相同能力的批处理入口,长时间神经
训练(论文级复现)建议用脚本在 GPU 环境运行。
